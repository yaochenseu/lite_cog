# M260C 语音功能实施计划

## 目标

在 Ubuntu 系统上分别实现以下功能：

| 功能 | 实现结果 |
|---|---|
| 语音唤醒 | 识别唤醒词并产生唤醒事件 |
| 语音转文字 | 将麦克风采集的语音转换成文字 |
| 声源定位 | 输出说话人的方向角度 |
| ROS1 接入 | 将以上功能提供给 ROS1 系统使用 |

## 实施原则

- 每个功能单独开发、运行和验收。
- 功能之间不直接绑定。
- 单项功能完成后再进行 ROS1 接入。
- 所有功能完成后再增加组合流程。

## 实施计划

| 阶段 | 工作内容 | 完成结果 |
|---|---|---|
| 第一阶段 | 确认设备连接和录音状态 | 设备可正常通信和录音 |
| 第二阶段 | 实现语音唤醒 | 唤醒词能够稳定触发事件 |
| 第三阶段 | 实现语音转文字 | 语音能够转换成文字 |
| 第四阶段 | 实现声源定位 | 能够获得说话方向角度 |
| 第五阶段 | 接入 ROS1 | 每个功能都能在 ROS1 中独立使用 |
| 第六阶段 | 组合功能 | 唤醒后自动进行语音识别 |

## 分阶段任务

### 1. 设备准备

- 确认 M260C 型号和连接状态。
- 验证麦克风录音。
- 验证设备信息读取。

### 2. 语音唤醒

- 读取唤醒事件。
- 单独运行唤醒功能。
- 测试不同距离下的唤醒效果。

### 3. 语音转文字

- 采集麦克风语音。
- 将语音转换成文字。
- 单独测试识别结果。

### 4. 声源定位

- 获取声源方向。
- 输出方向角度。
- 从不同方向进行测试。

### 5. ROS1 接入

- 分别接入语音唤醒、语音转文字和声源定位。
- 为每个功能提供独立启动方式。
- 验证三个功能可以分别运行。

### 6. 功能组合

- 语音唤醒后开始识别。
- 发布识别文字和声源方向。
- 验证完整语音交互流程。

## 验收标准

| 功能 | 验收标准 |
|---|---|
| 语音唤醒 | 说出唤醒词后能够触发一次唤醒事件 |
| 语音转文字 | 能够输出与语音内容对应的文字 |
| 声源定位 | 能够输出与说话方向对应的角度 |
| ROS1 接入 | 三个功能均可在 ROS1 中独立启动和使用 |
| 组合流程 | 唤醒后能够完成录音、识别和结果输出 |
